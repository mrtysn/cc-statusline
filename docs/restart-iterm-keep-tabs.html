Restart iTerm2, keep tabs

Goal

Quit and reopen iTerm2 while Claude sessions are busy, and come back to the same tabs in the same order, each showing the same session, with no session interrupted. This is a frequent step, for example when iTerm2 has a pending security update.

The owner chose:

  • On demand, not automatic on every launch.
  • Keep the exact tab order, not only the list of tabs.

What exists today

  • Sessions survive. Every clo session runs in the default tmux server, which is a child of launchd, not of iTerm2. iTerm2 shows each session through tmux -CC, so a quit only ends the control client.
  • One row at a time. Show Terminal and a double-click on a row both call focusTerminal. For a session with no terminal, it runs tmux -CC attach-session -t '=name' through runInNewTab, for that one session only.
  • No tab position is recorded. The README says so. A reattached tmux tab is added at the end of the hotkey window.
  • Restart All Sessions and tmux is the wrong tool. It stops every Claude, busy ones included ("cut off mid-turn"), and runs tmux kill-server.
  • Resume Closed Sessions and Finish Last Restart All only bring back sessions that have ended. A session still running in tmux is not theirs to touch.

Design

Three new items in the Session menu. The first two work alone, which covers iTerm2's own Install and Relaunch prompt: Save, then the update, then Restore.

Save iTerm Tabs

  1. Through AppleScript, read every tab of every iTerm2 window in order, hotkey window first. For each tab, read its current session's tmuxWindowPane variable and its tty.
  2. Map each pane number to its tmux session with tmux list-panes -a -F '#{pane_id}\t#{session_name}'.
  3. Mark a tab with no tmuxWindowPane as plain. Record its title and tty so it can be named later; it cannot come back.
  4. Write Application Support/CC Sessions/iterm-tabs.json beside restart-all.json. It holds the time saved and, per window, the ordered tabs: kind (tmux or plain), tmux session name and title.
  5. Report it in the status line, for example "Saved 6 tmux tabs, 1 plain tab".

Restore iTerm Tabs

  1. Read iterm-tabs.json. Refuse with a message when it is missing, or older than the tmux server's sessions it names.
  2. For each tmux tab, in saved order: skip a session that has ended or already has a client. Otherwise run the same attach focusTerminal uses, then wait until tmux list-clients -t '=name' shows a client and iTerm2 shows its tab, before the next one. A tab that does not appear within its time limit is reported and skipped.
  3. Report what came back, what had ended, and the plain tabs that could not return, by title.

Restart iTerm2, Keep Tabs

  1. Save, as above.
  2. Confirm in one dialog, naming the plain tabs that will be lost.
  3. Quit iTerm2 through AppleScript. Wait for its process to exit, then check that the tmux server still lists the saved sessions. If it does not, stop and report; restore nothing.
  4. Reopen iTerm2, wait until it answers Apple events, then Restore.

Keeping the order

No iTerm2 Python API is needed. iTerm2 adds each tmux tab at the end of the window, and AutoHideTmuxClientSession buries the gateway tab that opened it. So attaching the saved sessions one after another, each only after the previous tab is shown, rebuilds the saved order in a window that starts empty.

The restore must not go through clo, whose iterm-place-tmux-tab.py moves a tmux tab into the slot of the tab that launched it. focusTerminal's attach already avoids clo.

A window that is not empty at restore time breaks this. iTerm2 may open a default shell tab at launch, and the owner may open tabs before restoring. See Open questions.

Risks and unknowns

  • Whether quitting iTerm2 detaches or kills tmux windows is unverified. Two sessions created before the current iTerm2 launch were reattached afterwards (cc-sessions.log), but whether that iTerm2 quit or crashed is not recorded. The Restart item checks the tmux server after the quit and stops if sessions are gone, so a wrong guess costs no restore. It cannot bring killed sessions back.
  • iTerm2's quit confirmation. iTerm2 may ask before quitting with running sessions. The Restart item waits for the quit rather than answering for the owner.
  • Apple events after an install. Installing a new CC Sessions under a running copy makes macOS refuse its Apple events (-1743) until it is reopened. Every step here needs Apple events, so the feature works only after that reopen.
  • Several tmux servers. tmuxWindowPane is a pane number without its server. Save reads only the default server, as focusITermTmuxPane already does.

Testing

  • Self-test, on fixed output: AppleScript tab listings and list-panes text to the saved record, plain tabs included; the record to the attach order, skipping ended and attached sessions; refusal of a missing or stale record.
  • Live and read-only: Save on the running iTerm2, comparing the record with the tabs on screen.
  • Restore and Restart cannot be tested without quitting the owner's iTerm2. Their first real use is the live test, and the status line reports each step.

Open questions

  1. Which windows? All iTerm2 windows, each restored into its own window, or only the hotkey window.
  2. A tab already in the window at restore time, such as iTerm2's default shell tab at launch. Close it when it is an idle fresh shell, put the restored tabs after it, or refuse to restore until the window is empty.
  3. Plain tabs. Only name them in the report, or reopen each as a new shell in the same folder.
  4. Restore check. Should Restore refuse a record saved before the last restart, or more than a set time ago, or always run it.
