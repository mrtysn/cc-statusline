Restart iTerm2, keep tabs

Goal

Quit and reopen iTerm2 while Claude sessions are busy, and come back to the same tabs in the same order, each showing the same session, with no session interrupted. This is a frequent step, for example when iTerm2 has a pending security update.

The owner chose:

  • On demand, not automatic on every launch. Widened on 27 November 2026: the app also saves on its own, and Restore works after a reboot (see After a reboot).
  • Keep the exact tab order, not only the list of tabs.

What exists today

  • Sessions survive. Every clo session runs in the default tmux server, which is a child of launchd, not of iTerm2. iTerm2 shows each session through tmux -CC, so a quit only ends the control client.
  • One row at a time. Show Terminal and a double-click on a row both call focusTerminal. For a session with no terminal, it runs tmux -CC attach-session -t '=name' through runInNewTab, for that one session only.
  • No tab position is recorded. The README says so. A reattached tmux tab is added at the end of the hotkey window.
  • Restart All Sessions and tmux is the wrong tool. It stops every Claude, busy ones included ("cut off mid-turn"), and runs tmux kill-server.
  • Resume Closed Sessions and Finish Last Restart All only bring back sessions that have ended. A session still running in tmux is not theirs to touch.

Design

Three new items in the Session menu. The first two work alone, which covers iTerm2's own Install and Relaunch prompt: Save, then the update, then Restore.

Save iTerm Tabs

  1. Through AppleScript, read every window of iTerm2 in order, hotkey window first. Per window: whether it is the hotkey window, and the profile name of its first tab. Per tab, in order: its current session's tmuxWindowPane variable, tty, name and profile name.
  2. Map each pane number to its tmux session with tmux list-panes -a -F '#{pane_id}\t#{session_name}'.
  3. Mark a tab with no tmuxWindowPane as plain. Its process cannot come back, so record what lets the owner pick up: its shell's folder (lsof -a -p <pid> -d cwd), the foreground command and arguments (ps on its tty), and the last lines of its screen (iTerm2's AppleScript contents). The screen lines go in a file of their own beside the record, readable only by the owner (mode 600), since they can hold secrets.
  4. Write Application Support/CC Sessions/iterm-tabs.json beside restart-all.json. It holds the time saved and the windows in order. Each window has its kind (hotkey or normal), its profile name, and its ordered tabs. Each tab has its kind (tmux or plain), name and profile; a tmux tab adds its session name, and a plain tab its folder, command and the path of its screen file.
  5. Report it in the message bar under the session list, for example "Saved 6 tmux tabs, 1 plain tab".

Restore iTerm Tabs

  1. Read iterm-tabs.json, whatever its age; refuse with a message only when it is missing. A tab closed on purpose after the save comes back if its session still runs, and the owner closes it again.
  2. Run on a background queue, as Restart All does, so the app never waits on iTerm2 on its main thread.
  3. Per saved window: the hotkey window is the existing one (made with its profile when absent); a normal window is created with its saved profile. Tabs already in a window are kept, and the restored tabs follow them.
  4. One loop over each window's tabs in saved order. Before creating each tab, select the window's last tab: this iTerm2 adds a new tab after the current one, not at the end (AddNewTabAtEndOfTabs is off), so a click during the restore would otherwise put tabs out of place.
    • A tmux tab: resume a session that has ended (see After a reboot), skip one that iTerm2 already shows (a tab with its pane's tmuxWindowPane). Otherwise attach it in control mode, as focusTerminal does, and wait until iTerm2 shows its tab before the next one. Then give the tab its title back: a reattach does not replay the title escape the program wrote, so the tab shows only its job ("claude"). The title tmux keeps for the pane (Claude Code's own) is written again as an OSC 0 escape to the pane's tty, which tmux passes to iTerm2 as output; when the pane has none, the session's name in CC Sessions is used. A tab that does not appear within its time limit is reported and skipped.
    • A plain tab: open a shell that changes to the saved folder and prints, as # comment lines, the command that was running, then shows the saved screen lines with cat on their file. Nothing from the screen goes through AppleScript or shell quoting.
  5. Report what came back, what had ended, and what did not appear.

Restart iTerm2, Keep Tabs

  1. Save, as above.
  2. Confirm in one dialog, naming the plain tabs whose processes will end.
  3. On a background queue: ask iTerm2 to quit through AppleScript, with a time limit on the Apple event. iTerm2 may show its own "Quit iTerm2?" prompt; the owner answers it. If iTerm2 is still running when the limit passes, the owner cancelled: stop and report, restore nothing.
  4. Wait for the iTerm2 process to exit, then for tmux list-clients to be empty, since tmux drops each client a moment after it sees the hangup. Then check that the tmux server still lists the saved sessions; if it does not, stop and report, restore nothing.
  5. A busy session's hook may launch iTerm2 again before this step (see Risks). If iTerm2 is already running, use it; otherwise open it. Wait until it answers Apple events, then Restore.

After a reboot

A reboot or a lost tmux server ends every session, so the first design restored nothing: the record held only tmux session names. Added on 27 November 2026, after exactly that.

  • Record. Each tmux tab also keeps its Claude session id, launch folder, current folder, model, effort, permission mode and name. The record keeps the boot session id, the tmux server's pid and iTerm2's pid.
  • Which id. clo's record for the tmux name comes first, since it follows /clear and resume; one from another folder belongs to another session and is ignored. clo can delete its record, so the saved id is the fallback.
  • Restore. A running tmux session is attached (on another server or boot, only when it holds the saved Claude session). Otherwise the Claude session is resumed in the tab's position; one running under another tmux name is attached; one running outside tmux is skipped; a tab with no session, or no prompt yet, becomes a shell that says so. A sheet asks first when anything will be resumed or the Mac restarted, and a sheet lists every outcome.
  • Automatic save. Every 30 seconds, when the tabs changed. A record from another boot, tmux server or iTerm2 is held until restored in full or saved over by hand; the current tabs go to iterm-tabs-current.json, which replaces the held record once its own run has ended with a Claude session in it. A smaller set must last 60 seconds, and a shutdown notice stops saving for five minutes.
  • Not recovered. A turn cut off mid-run, plain tabs' programs, scrollback, tabs of another tmux server.
  • Not yet seen in use. The shutdown guard, and a real restore after a reboot: the self-test covers the plan and the order on fixed data only.

Keeping the order

No iTerm2 Python API is needed. iTerm2 adds each tmux tab at the end of the window, and AutoHideTmuxClientSession buries the gateway tab that opened it. A new plain tab goes after the current tab, so the restore selects the window's last tab before each one. Creating every tab in one loop, in saved order, each only after the previous one is shown, rebuilds the saved order after whatever tabs the window already has.

An attach goes through clo --attach, which moves nothing. A resume goes through clo --run-claude, whose iterm-place-tmux-tab.py moves the new tmux tab into the slot of the tab that launched it, the position the restore chose; the restore waits for each new tab before the next.

Risks and unknowns

  • Quitting iTerm2 detaches tmux; it does not kill it. In iTerm2's source, kill-window is sent only from the close prompts the owner answers; a quit closes windows and the gateway detaches. That was read on iTerm2's master branch, not the installed release tag. A tmux server older than the running iTerm2 has survived one iTerm2 launch. The Restart item still checks the tmux server after the quit and stops if sessions are gone.
  • iTerm2's quit prompt. iTerm2 may ask before quitting. The Restart item waits on it off the main thread, with a time limit, and never answers it.
  • iTerm2 relaunched by a hook. While quitting, iTerm2 refuses new it2 API connections, so a Claude hook cannot relaunch it mid-quit (iTermApplicationDelegate.m, the comment before stopAcceptingConnections). Once it has exited, a busy session's hook that sends iTerm2 an Apple event can launch it again. The Restart item then restores into that iTerm2 instead of opening another, and the default tab it may have opened stays first.
  • Apple events after an install. Installing a new CC Sessions under a running copy makes macOS refuse its Apple events (-1743) until it is reopened. Every step here needs Apple events, so the feature works only after that reopen.
  • Several tmux servers. tmuxWindowPane is a pane number without its server. Save reads only the default server, as focusITermTmuxPane already does.

Testing

  • Self-test, on fixed output only: AppleScript tab listings and list-panes text to the saved record, plain tabs included; the record to the restore plan, in order, skipping ended sessions and those already shown; refusal of a missing record; a record of any age accepted.
  • No test runs against the owner's live sessions or running iTerm2 while building: the owner asked for that. Save, Restore and Restart are first used for real by the owner, and the message bar under the session list reports each step.

Open questions

  1. Which windows? Decided: all iTerm2 windows, each restored into its own window with its tabs in order.
  2. A tab already in the window at restore time, such as iTerm2's default shell tab at launch. Decided: keep it, and add the restored tabs after it.
  3. Plain tabs. Decided: reopen each as a shell in its saved folder, printing what was running and its last screen lines as comments.
  4. Restore check. Decided: always restore from the saved record, whatever its age.
